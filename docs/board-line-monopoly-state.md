# 보드 라인 독점 조회 계약

`GET /api/v1/board/me`의 기존 응답에 아래 필드를 추가한다. 로그인한 현재 팀의 기록만 반환하며, 팀 ID를 받는 별도 요청이나 지급 API는 사용하지 않는다.

```json
{
  "code": "SUCCESS",
  "data": {
    "team_id": "authenticated-team-uuid",
    "line_monopolies": [
      { "line_number": 1, "earned_score": 225, "is_category_bonus": true, "monopolized_at": "2026-10-26T00:00:00Z" }
    ]
  }
}
```

- `earned_score`는 JSON number이며 실제 저장된 지급액이다. 현재 문제 점수나 30%/45% 공식으로 프론트엔드가 다시 계산하지 않는다. 0도 유효한 확정 지급액이다.
- 서버의 `line_number`로 6개 라인을 구성하고 START·찬스·룰렛·공항 등 6개 특수 칸은 제외한다. 기존 6색 Rail 컴포넌트와 스타일은 변경하지 않는다.
- 인증 컨텍스트의 팀 ID와 응답 `team_id`가 일치하는 경우에만 지급 기록을 적용한다. 누락된 필드, 잘못된 점수, 중복 기록, 팀 불일치는 지급 미확인이다.
- 기록이 없고 5/5를 풀지 않은 라인은 미완료, 5/5를 풀었지만 기록이 없는 라인은 지급 미확인, 유효한 확정 기록이 있는 라인은 독점 완료다.
- 최초 보드 조회·페이지 복귀·새로고침 및 보이는 화면에서 15초 간격/포커스 복귀로 GET을 갱신한다. 이 갱신은 이동 좌표·주사위·이벤트를 바꾸지 않는다. 중복 요청을 막고 해제 시 취소하며, 팀 불일치 또는 이동 중 도착한 응답은 적용하지 않는다.
- 배포 순서: 백엔드 조회 필드 추가 → 프론트엔드. 구버전 백엔드에는 기존과 같이 지급 미확인으로 표시하고 완료/점수를 추정하지 않는다.
- 과거 5/5인데 기록이 없는 팀의 보너스를 GET에서 새로 지급하지 않는다. 그런 데이터가 있다면 별도의 운영 감사/승인이 필요하다.

검증은 운영 문제 제출 없이 격리 Django 테스트 DB의 실제 API 응답을 프론트엔드에 네트워크 모킹하여 수행한다. 실 운영 데이터 검증과 구분한다.
