# 보드 라인 독점 조회 계약

병합된 백엔드 PR #182의 `GET /api/v1/board/me` 응답을 사용한다. 백엔드는 변경하거나 실행하지 않는다. 로그인한 현재 팀의 기록만 반환하며 별도 API는 신설하지 않는다.

```json
{
  "code": "SUCCESS",
  "data": {
    "line_monopolies": [
      { "line_number": 1, "earned_score": 225, "is_category_bonus": true }
    ]
  }
}
```

- `earned_score`는 JSON number이며 실제 저장된 지급액이다. 현재 문제 점수나 30%/45% 공식으로 프론트엔드가 다시 계산하지 않는다. 0도 유효한 확정 지급액이다.
- 서버의 `line_number`로 6개 라인을 구성하고 START·찬스·룰렛·공항 등 6개 특수 칸은 제외한다. 기존 6색 Rail 컴포넌트와 스타일은 변경하지 않는다.
- 응답에 `team_id`는 없다. 조회를 시작한 인증 컨텍스트(사용자·팀)에 응답을 묶고, 팀 전환·해제·이동·더 최신 전체 상태 조회 이후의 늦은 응답은 적용하지 않는다. 누락된 필드, 잘못된 점수, 중복 기록은 main의 검증기를 통해 지급 미확인으로 남긴다.
- 기록이 없고 5/5를 풀지 않은 라인은 미완료, 5/5를 풀었지만 기록이 없는 라인은 지급 미확인이다. main의 정책대로 유효한 지급 기록과 해당 라인의 CLEARED 상태가 모두 있어야 완료 Rail을 표시한다.
- 최초 보드 조회·페이지 복귀·새로고침 및 보이는 화면에서 15초 간격/포커스 복귀로 GET을 갱신한다. 이 갱신은 이동 좌표·주사위·이벤트를 바꾸지 않는다. 중복 요청을 막고 해제 시 취소하며, 팀 불일치 또는 이동 중 도착한 응답은 적용하지 않는다.
- 구버전 백엔드에는 기존과 같이 지급 미확인으로 표시하고 완료/점수를 추정하지 않는다. main의 lossless JSON 파서로 큰 지급 정수도 보존한다.
- 다음 응답에서 지급 기록이 삭제되면 Rail을 제거하고, 지급액이 바뀌면 합계와 라인 점수를 교체한다. 프론트엔드는 점수 지급·회수 요청을 하지 않는다.
- 과거 5/5인데 기록이 없는 팀의 보너스를 GET에서 새로 지급하지 않는다. 그런 데이터가 있다면 별도의 운영 감사/승인이 필요하다.

이번 검증은 백엔드 실행 없이 PR #182 계약에 맞춘 프론트엔드 mock API로 수행한다. 과거 Django 테스트 결과나 실 운영 검증과 혼동하지 않는다. PR #205의 외곽 Rail, PR #220의 찬스 선택 복구 및 main의 응답 역전 방지 코드를 유지한다.
