# KOTH 수집 상태와 관리자 정리 재시도

## 수정

- 관리자 대시보드와 인스턴스 목록의 FAILED 행에 정리 재시도 추가
- 접수 응답은 대상 ID와 CLEANUP_PENDING 상태를 확인하고, 정리 완료와 구분
- 처리 중 중복 클릭 차단, 응답 유실·대상 없음·상태 변경 시 안내 후 목록 갱신
- KOTH 순위표에도 수집 실패·대기 상태와 마지막 성공 시각 표시
- 점수 조회 요청 실패는 수집 실패와 따로 안내하고, 순위 없는 0점 행은 대시로 표시

## 화면 검증 범위

운영 사이트의 기존 프론트 13ee7af에서 누락을 확인한 뒤 수정 화면을 운영 백엔드 610fa4d에 연결해 검증했다
검증 전용 계정·문제·수집 이력을 사용했고, 브라우저 목록은 해당 QA 항목만 보이도록 필터링했다
수정본을 운영 사이트에 배포한 검증은 아니다

| 항목 | 결과 | 환경 |
| --- | --- | --- |
| 수집 실패 → 정상 수집 | 실패 안내가 사라지고 실제 0점·마지막 수집 시각 표시 | 실제 운영 API와 QA 수집 이력 |
| 내 팀 점수 조회 연결 끊김 → 복구 | 조회 실패를 표시한 뒤 자동 갱신으로 복구 | 운영 API를 사용하는 브라우저의 요청만 중단 |
| 관리자 버튼 → 실제 정리 API | POST 1회, 404 안내, FAILED 유지, 실패 감사 기록 1건 | 실제 운영 백엔드·스케줄러, 리소스 없는 QA 이력 |
| 202 접수 → CLEANUP_PENDING → CLEANED | 접수와 완료를 구분하고 재조회로 화면 갱신 | 계약 응답을 주입한 UI 검증 |
| 목록·대시보드의 더블클릭 | 처리 중 POST 1회 | 계약 응답에 지연을 넣은 UI 검증 |
| 다른 인스턴스의 접수 응답 | 완료로 처리하지 않고 안내 유지 | 계약 오류 응답을 주입한 UI 검증 |
| 관리자 요청 응답 끊김 | 결과 미확인 안내, 자동 재전송 없음 | 해당 브라우저의 요청만 중단 |
| 390px 모바일 | 수집 시각·점수·순위 표시 확인 | 실제 운영 API에 연결한 수정 화면 |

202 이후 실제 workload 삭제·브로커 예약 반납을 이 검증으로 입증하지 않는다
FAILED만으로 스케줄러의 재시도 가능 여부를 확정하지 않으며, 서버가 거절하면 그 오류를 안내한다
강제 정리 API로 자동 우회하지 않는다
